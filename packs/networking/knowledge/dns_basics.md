# DNS域名解析基础

## 什么是DNS？

DNS（Domain Name System，域名系统）是互联网的"电话本"。它将人类容易记忆的域名（如 `www.baidu.com`）转换为计算机需要的IP地址（如 `110.242.68.66`）。

没有DNS，你要记住每个网站的IP地址——就像没有通讯录，你要记住所有人的电话号码。

## 域名的层次结构

域名从右到左，层级递减：

```
www.baidu.com.
│   │     │  │
│   │     │  └── 根域（.），通常省略不写
│   │     └────── 顶级域名（Top-Level Domain, TLD）
│   └──────────── 二级域名（Second-Level Domain）
└──────────────── 三级域名（子域名）
```

### 顶级域名分类

| 类型 | 示例 | 说明 |
|------|------|------|
| 通用顶级域名（gTLD） | .com、.org、.net | 最常用 |
| 国家代码顶级域名（ccTLD） | .cn、.jp、.uk | 按国家/地区 |
| 新通用顶级域名 | .app、.dev、.ai | 2012年后新增 |

## DNS服务器层次

DNS采用**分层、分布式的服务器架构**：

```
                    ┌─────────────┐
                    │  根域名服务器  │ 全球13组，知道所有TLD服务器的地址
                    └──────┬──────┘
            ┌──────────────┼──────────────┐
       ┌────▼────┐   ┌────▼────┐   ┌────▼────┐
       │.com服务器│   │.cn服务器 │   │.org服务器│  TLD服务器，知道权威DNS地址
       └────┬────┘   └────┬────┘   └────┬────┘
       ┌────▼────┐        │             │
       │example的│        │             │
       │权威DNS  │        │             │  权威DNS，知道具体域名的IP
       └─────────┘        │             │
```

### 各级DNS服务器职责

- **根域名服务器**：全球13组（并非13台，每组有数百台镜像）。知道所有TLD服务器的地址，是DNS查询的起点。
- **TLD服务器**：管理某个顶级域（如.com）下所有域名的权威DNS地址。
- **权威DNS服务器**：存储某个具体域名（如baidu.com）的DNS记录，给出最终的IP地址。
- **本地DNS服务器**（递归解析器）：由ISP或公共DNS提供（如8.8.8.8、114.114.114.114），帮客户端完成递归查询并缓存结果。

## DNS解析流程

### 递归查询 vs 迭代查询

当你在浏览器输入 `www.example.com`：

**方式1：递归查询**（本地DNS代劳）

```
客户端 → 本地DNS："帮我查 www.example.com"
        本地DNS → 根服务器："com的服务器在哪？"
        本地DNS ← 根服务器：".com的服务器是xxx"
        本地DNS → TLD服务器："example.com的权威DNS在哪？"
        本地DNS ← TLD服务器："权威DNS是yyy"
        本地DNS → 权威DNS："www.example.com的IP是什么？"
        本地DNS ← 权威DNS："IP是93.184.216.34"
客户端 ← 本地DNS："查到了，IP是93.184.216.34"
```

客户端只发一次请求，本地DNS完成所有查询步骤后返回结果。

**方式2：迭代查询**（客户端自己来）

```
客户端 → 根服务器："www.example.com的IP是什么？"
客户端 ← 根服务器："我不知道，但.com服务器在xxx，你自己去问"
客户端 → TLD服务器："www.example.com的IP是什么？"
客户端 ← TLD服务器："我不知道，但权威DNS是yyy，你自己去问"
客户端 → 权威DNS："www.example.com的IP是什么？"
客户端 ← 权威DNS："IP是93.184.216.34"
```

实际应用中，客户端使用递归方式把工作交给本地DNS，本地DNS用迭代方式逐级查询。

## DNS缓存

DNS缓存是提升解析速度的关键，存在于多个层级：

| 缓存位置 | 缓存内容 | 有效时间 | 清理方式 |
|----------|----------|----------|----------|
| 浏览器缓存 | 最近访问的域名 | 1-2分钟 | 清除浏览器数据 |
| 操作系统缓存 | 系统级DNS记录 | 按TTL | `ipconfig /flushdns` |
| 路由器缓存 | 局域网所有设备的DNS | 按TTL | 重启路由器 |
| ISP/本地DNS缓存 | 大量常用域名 | 按TTL | 不可控 |

### TTL（Time To Live）

每条DNS记录都有一个TTL值（单位：秒），决定缓存的有效期。

- 短TTL（60-300秒）：方便快速切换IP（CDN、故障转移）
- 长TTL（86400秒=24小时）：减轻DNS服务器负载

**注意**：即使修改了DNS记录，各级缓存也要等TTL过期才会更新——这就是"DNS传播延迟"。

## 常见DNS记录类型

| 类型 | 全称 | 用途 | 示例 |
|------|------|------|------|
| A | Address | 域名→IPv4地址 | example.com → 93.184.216.34 |
| AAAA | IPv6 Address | 域名→IPv6地址 | example.com → 2606:2800:220:1:... |
| CNAME | Canonical Name | 域名别名 | www.example.com → example.com |
| MX | Mail Exchange | 邮件服务器 | example.com → mail.example.com |
| NS | Name Server | 权威DNS服务器 | example.com → ns1.example.com |
| TXT | Text | 任意文本（验证/SPF） | "v=spf1 include:..." |
| PTR | Pointer | IP→域名（反向解析） | 34.216.184.93 → example.com |

## DNS安全

### DNS劫持

攻击者篡改DNS响应，将用户引导到恶意网站。防范：使用DoH（DNS over HTTPS）或DoT（DNS over TLS）加密DNS查询。

### DNS污染

在DNS查询路径中注入虚假响应，用于内容审查或攻击。防范：使用加密DNS或VPN。

### DNSSEC

通过数字签名验证DNS响应的真实性，防止伪造和篡改。用了DNSSEC后，攻击者即使拦截了DNS查询也无法伪造响应——因为签名验证会失败。

> DNS是互联网的入口。没有DNS，即使网络连通、服务器运行正常，用户也无法用域名访问任何网站。理解DNS，就是理解了"互联网是如何找到目的地的"。

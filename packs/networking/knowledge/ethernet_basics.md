# 以太网与MAC地址基础

## 什么是以太网？

以太网（Ethernet）是目前最主流的局域网（LAN）技术标准。从你家Wi-Fi路由器后面的网线接口，到数据中心里密密麻麻的服务器的网络接口，绝大多数都使用以太网协议。

以太网工作在OSI模型的**第1层（物理层）和第2层（数据链路层）**。

## MAC地址

### 什么是MAC地址？

MAC地址（Media Access Control Address）是**烧录在网卡上的物理地址**，全球唯一。

- **长度**：48位（6字节）
- **表示法**：十六进制，每字节用冒号或横线分隔，如 `00:1A:2B:3C:4D:5E`
- **结构**：
  - 前24位：OUI（Organizationally Unique Identifier），由IEEE分配给网卡制造商
  - 后24位：制造商自行分配的设备标识

> 看MAC地址的前24位就能知道制造商。比如 `00:1A:2B` 代表某厂商，`F0:18:98` 代表苹果公司。

### MAC地址 vs IP地址

| 对比维度 | MAC地址 | IP地址 |
|----------|---------|--------|
| 层级 | 数据链路层（第2层） | 网络层（第3层） |
| 性质 | 物理地址，出厂固化 | 逻辑地址，可配置 |
| 范围 | 局域网内使用 | 跨网络使用 |
| 类比 | 身份证号（全球唯一） | 手机号（可更换） |
| 长度 | 48位 | 32位（IPv4）/ 128位（IPv6） |

## 以太网帧结构

以太网帧是数据链路层的基本传输单元，结构如下：

```
┌──────────────┬──────────────┬──────────┬──────────────────┬──────────┐
│  目标MAC地址  │  源MAC地址    │ 类型/长度 │      数据         │  FCS校验  │
│   6 字节      │   6 字节      │  2 字节   │   46-1500 字节    │  4 字节   │
└──────────────┴──────────────┴──────────┴──────────────────┴──────────┘
```

- **目标MAC地址**：接收方的MAC地址。全F（FF:FF:FF:FF:FF:FF）表示广播。
- **源MAC地址**：发送方的MAC地址。
- **类型/长度**：标识上层协议类型（如0x0800表示IPv4，0x0806表示ARP）。
- **数据**：承载上层协议的数据（IP数据包等），最少46字节，最多1500字节（MTU）。
- **FCS**：帧校验序列，用于检测传输错误。

## 交换机的工作原理

交换机工作在数据链路层，核心功能是**基于MAC地址的帧转发**。

### 三大核心功能

1. **地址学习（Learning）**
   - 交换机每收到一个帧，就记录 "源MAC地址 → 接收端口" 的映射
   - 这些映射存储在 **MAC地址表**（也叫 CAM 表）中
   - 每个条目的有效期通常为300秒，过期自动清除

2. **转发/过滤（Forwarding/Filtering）**
   - 收到帧后，查目标MAC地址在不在MAC地址表里
   - 在 → 从对应端口**单播转发**（不惊动其他端口）
   - 不在 → **泛洪**（Flooding），向除了接收端口之外的所有端口发送

3. **环路避免（Loop Prevention）**
   - 使用STP（生成树协议）检测并阻断冗余链路
   - 防止广播帧在环路中无限循环

### 交换机 vs 集线器

| 对比 | 交换机（Switch） | 集线器（Hub） |
|------|-----------------|--------------|
| 工作层级 | 第2层（数据链路层） | 第1层（物理层） |
| 转发方式 | 按MAC地址定向转发 | 向所有端口广播 |
| 冲突域 | 每个端口独立 | 所有端口共享 |
| 效率 | 高，可同时多路通信 | 低，同一时间只能一路通信 |
| 监听风险 | 低（不广播） | 高（所有端口都能收到） |

## ARP协议

ARP（Address Resolution Protocol，地址解析协议）解决的核心问题：**已知IP地址，求MAC地址**。

### 工作流程

假设主机A（192.168.1.10）想和主机B（192.168.1.20）通信：

```
1. A查自己的ARP缓存表 → 没有B的MAC地址记录

2. A广播ARP请求帧：
   "谁的IP是192.168.1.20？请把你的MAC地址告诉192.168.1.10！"
   目标MAC：FF:FF:FF:FF:FF:FF（广播地址）

3. 交换机收到广播帧 → 泛洪到所有端口（除接收端口）

4. B收到ARP请求 → 发现问的是自己 → 单播回复：
   "我是192.168.1.20，我的MAC地址是BB:BB:BB:BB:BB:BB"
   目标MAC：A的MAC地址（单播）

5. A收到ARP响应 → 把 "192.168.1.20 → BB:BB:BB:BB:BB:BB" 记入ARP缓存

6. 后续通信直接查ARP缓存，无需再广播
```

### ARP缓存

每台主机维护一个ARP缓存表，记录IP→MAC的映射。在Windows上可以用 `arp -a` 查看。

缓存条目有过期时间（通常几分钟到几十分钟），过期后需要重新发送ARP请求。

### 免费ARP（Gratuitous ARP）

一种特殊的ARP消息——主机主动广播自己的IP和MAC映射，用于：
- 检测IP地址冲突（如果收到回复说明有人在用这个IP）
- 更新其他主机的ARP缓存（IP没变但MAC变了，如更换网卡）

> ARP是局域网通信的基础。没有ARP，即使知道对方IP地址，数据帧也无法封装正确的目标MAC地址。

## 广播域

**广播域**是指网络中能收到同一广播帧的所有节点的集合。

- 交换机的所有端口默认属于同一个广播域
- 路由器隔离广播域（路由器不转发广播帧）
- VLAN可以分割广播域

广播域太大带来的问题：
- 广播风暴：大量广播帧耗尽网络带宽
- 安全风险：广播帧可以被域内所有主机接收
- 性能下降：每台主机都要处理大量无用的广播帧

# TCP与HTTP基础

## TCP概述

TCP（Transmission Control Protocol，传输控制协议）是互联网最核心的协议之一，工作在OSI传输层（第4层）。

**TCP的目标：在不可靠的IP网络之上，提供可靠的端到端数据传输。**

### TCP的核心特性

| 特性 | 说明 |
|------|------|
| 面向连接 | 通信前必须建立连接（三次握手） |
| 可靠传输 | 确认应答、超时重传、数据校验 |
| 流量控制 | 滑动窗口机制，防止发送方太快 |
| 拥塞控制 | 慢启动、拥塞避免，防止网络过载 |
| 全双工 | 双方可同时收发数据 |
| 字节流 | 不保留消息边界，数据是连续的字节流 |

### TCP vs UDP

| 对比 | TCP | UDP |
|------|-----|-----|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠（确认+重传） | 不可靠（尽力而为） |
| 顺序 | 保证顺序 | 不保证顺序 |
| 速度 | 较慢 | 较快 |
| 头部开销 | 20字节 | 8字节 |
| 适用场景 | 网页、邮件、文件传输 | 视频直播、在线游戏、DNS查询 |

## 三次握手

TCP建立连接必须经过"三次握手"，目的是**确认双方的收发能力都正常**。

```
客户端                          服务器
  |                               |
  |------ SYN (seq=x) ----------->|  第1次：客户端说"你好，能连吗？"
  |                               |         (客户端证明自己有发送能力)
  |                               |
  |<--- SYN+ACK (seq=y,ack=x+1) --|  第2次：服务器说"你好，可以连，你收得到吗？"
  |                               |         (服务器证明自己有收发能力)
  |                               |
  |------ ACK (ack=y+1) --------->|  第3次：客户端说"收到，开始传数据吧！"
  |                               |         (客户端证明自己有接收能力)
  |                               |
  |<===== 连接建立，开始传输 =====>|
```

### 为什么是三次，不是两次？

两次握手的问题：无法防止已失效的连接请求到达服务器。

假设客户端发出的第一个SYN因为网络延迟很久才到服务器：
- 两次握手：服务器直接进入ESTABLISHED状态，分配资源等待数据。但客户端已经放弃了这个连接——服务器资源被白白浪费。
- 三次握手：服务器先回复SYN-ACK，等待客户端的ACK确认。如果没有收到确认，服务器知道连接失败，不分配资源。

### 常见TCP状态

| 状态 | 含义 |
|------|------|
| LISTEN | 服务器等待连接请求 |
| SYN-SENT | 客户端已发送SYN，等待匹配的SYN |
| SYN-RECEIVED | 服务器已收到SYN并发送SYN-ACK，等待ACK |
| ESTABLISHED | 连接已建立，正常通信中 |
| FIN-WAIT-1 | 主动关闭方已发送FIN |
| TIME-WAIT | 主动关闭方等待2MSL（确保最后的ACK到达） |
| CLOSED | 连接已关闭 |

## 四次挥手

TCP断开连接需要四次挥手，因为TCP是全双工的——双方都需要独立关闭自己的发送方向。

```
客户端                          服务器
  |                               |
  |------ FIN (seq=u) ----------->|  第1次：客户端说"我说完了，我要关了"
  |                               |
  |<----- ACK (ack=u+1) ---------|  第2次：服务器说"好的，我知道你说完了"
  |                               |         (但服务器可能还有数据要发)
  |                               |
  |<----- FIN (seq=v) -----------|  第3次：服务器说"我也说完了，我也要关了"
  |                               |
  |------ ACK (ack=v+1) --------->|  第4次：客户端说"好的，再见"
  |                               |
  |  (TIME-WAIT 等待2MSL)         |
  |<===== 连接关闭 ==============>|
```

### 为什么是四次？

因为TCP是全双工的，每个方向必须独立关闭：
- 客户端→服务器的方向关闭（第1-2次）
- 服务器→客户端的方向关闭（第3-4次）

### 关于TIME-WAIT

客户端发送最后一个ACK后，进入TIME-WAIT状态，等待2MSL时间。
- MSL（Maximum Segment Lifetime）= 报文最大生存时间，通常2分钟。
- 目的：确保最后的ACK能到达服务器。如果ACK丢失，服务器会重发FIN，客户端还能响应。
- 同时让网络中该连接的所有残留报文都消失，不影响新连接。

## HTTP基础

HTTP（HyperText Transfer Protocol，超文本传输协议）是Web的基础协议，工作在应用层，依赖TCP传输。

### HTTP请求格式

```
GET /index.html HTTP/1.1           ← 请求行：方法 + 路径 + 版本
Host: www.example.com              ← 请求头：主机名
User-Agent: Mozilla/5.0            ← 请求头：客户端信息
Accept: text/html                  ← 请求头：接受的内容类型
Connection: keep-alive             ← 请求头：保持连接
                                   ← 空行（头与体之间的分隔）
                                   ← 请求体（GET请求通常为空）
```

### HTTP响应格式

```
HTTP/1.1 200 OK                    ← 状态行：版本 + 状态码 + 原因短语
Date: Mon, 01 Jan 2024 12:00:00   ← 响应头
Content-Type: text/html; utf-8    ← 响应头
Content-Length: 1234              ← 响应头
                                   ← 空行
<!DOCTYPE html>                    ← 响应体
<html>...</html>
```

### 常见HTTP方法

| 方法 | 含义 | 安全 | 幂等 |
|------|------|------|------|
| GET | 获取资源 | ✓ | ✓ |
| POST | 创建资源/提交数据 | ✗ | ✗ |
| PUT | 更新资源（全量替换） | ✗ | ✓ |
| PATCH | 更新资源（部分修改） | ✗ | ✗ |
| DELETE | 删除资源 | ✗ | ✓ |
| HEAD | 同GET但只返回头部 | ✓ | ✓ |
| OPTIONS | 查询支持的方法 | ✓ | ✓ |

> **安全**：不改变服务器状态。**幂等**：执行多次和执行一次效果相同。

### 常见HTTP状态码

| 状态码 | 原因短语 | 含义 |
|--------|----------|------|
| 1xx | 信息 | 请求已收到，继续处理 |
| 200 | OK | 成功，响应正常 |
| 301 | Moved Permanently | 永久重定向，资源已移到新URL |
| 302 | Found | 临时重定向 |
| 304 | Not Modified | 资源未修改，使用缓存 |
| 400 | Bad Request | 客户端请求有语法错误 |
| 401 | Unauthorized | 需要身份认证 |
| 403 | Forbidden | 服务器拒绝访问（权限不够） |
| 404 | Not Found | 资源不存在 |
| 500 | Internal Server Error | 服务器内部错误 |
| 502 | Bad Gateway | 网关错误（上游服务器无响应） |
| 503 | Service Unavailable | 服务器暂时不可用（过载/维护） |

**记忆口诀**：2xx成功、3xx重定向、4xx客户端错误、5xx服务端错误。

### HTTP/1.1 持久连接

HTTP/1.1默认开启 `Connection: keep-alive`，同一个TCP连接可以发送多个HTTP请求，避免了反复建立和断开TCP连接的开销。

```
HTTP/1.0（非持久）：
  建立TCP → 发送请求 → 接收响应 → 关闭TCP → 建立TCP → ...

HTTP/1.1（持久）：
  建立TCP → 请求1→响应1→请求2→响应2→...→ 关闭TCP
```

### HTTPS简述

HTTPS = HTTP + TLS/SSL，在TCP三次握手之后、HTTP通信之前，增加了TLS握手：

```
TCP三次握手 → TLS握手（证书交换+密钥协商） → 加密的HTTP通信
```

HTTPS提供：
- **机密性**：内容加密，防窃听
- **完整性**：防篡改，数据被改会检测到
- **身份认证**：证书验证服务器身份，防冒充

### DNS查询简要补充

DNS（Domain Name System，域名系统）将域名解析为IP地址：

1. 客户端查本地缓存 → 有则直接用
2. 无缓存 → 向本地DNS服务器发起查询
3. 本地DNS无缓存 → 从根域名服务器开始递归查询：
   - 根DNS：".com的服务器在xxx"
   - .com顶级DNS："example.com的权威DNS在yyy"
   - 权威DNS："www.example.com的IP是1.2.3.4"
4. 逐级返回结果，各级缓存记录
5. 客户端获得IP地址，开始TCP连接

DNS使用UDP协议（端口53），查询速度快。大型响应或区域传输时也会用到TCP。

> TCP确保数据可靠到达，HTTP定义了如何请求和响应的格式，DNS解决域名到IP的映射——三者配合，构成了你每天上网的基础。

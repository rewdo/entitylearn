# OSI七层模型基础

## 什么是OSI模型？

OSI（Open Systems Interconnection，开放系统互连）模型是国际标准化组织（ISO）制定的网络通信参考模型。它把网络通信划分成七个层次，每一层都有明确的职责，上层依赖下层提供的服务，下层为上层屏蔽实现细节。

**核心思想：分层解耦。** 每一层只关心自己的事情，不需要知道其他层的内部实现。

## 七层概览

| 层号 | 名称 | 英文 | 核心职责 | 典型设备/协议 |
|------|------|------|----------|--------------|
| 7 | 应用层 | Application | 为用户提供网络服务接口 | HTTP、DNS、FTP、SMTP |
| 6 | 表示层 | Presentation | 数据格式转换、加密解密、压缩 | SSL/TLS、JPEG、ASCII |
| 5 | 会话层 | Session | 建立、管理、终止会话 | NetBIOS、RPC |
| 4 | 传输层 | Transport | 端到端可靠传输、流量控制 | TCP、UDP |
| 3 | 网络层 | Network | 逻辑寻址与路由选择 | IP、路由器、ICMP |
| 2 | 数据链路层 | Data Link | 物理寻址（MAC）、帧封装、差错检测 | 以太网、交换机、ARP |
| 1 | 物理层 | Physical | 比特流传输、物理介质 | 网线、光纤、集线器、Wi-Fi |

## 重点层级详解

### 第2层：数据链路层（Data Link Layer）

**一句话：负责相邻节点之间可靠的帧传输。**

交换机就工作在这一层。关键概念：

- **MAC地址**：48位物理地址，每块网卡出厂唯一。例如 `00:1A:2B:3C:4D:5E`，前24位是厂商标识（OUI），后24位是设备标识。
- **以太网帧**：数据链路层的传输单元。结构：目标MAC（6字节）+ 源MAC（6字节）+ 类型（2字节）+ 数据（46-1500字节）+ FCS校验（4字节）。
- **交换机自学习**：交换机通过记录源MAC→端口的映射来构建MAC地址表，实现精确转发而非广播。
- **ARP协议**：Address Resolution Protocol，在已知IP地址的情况下查询对应的MAC地址。工作原理：广播ARP请求"谁的IP是192.168.1.1？"，目标主机单播回应"是我，我的MAC是xx:xx"。

> 数据链路层解决的是**同一网络内点到点**的通信问题。它不关心IP地址，不关心路由，只管把帧从一根网线的一端准确送到另一端。

### 第3层：网络层（Network Layer）

**一句话：负责不同网络之间的寻址与路由。**

路由器就工作在这一层。关键概念：

- **IP地址**：逻辑地址，可以灵活分配。IPv4是32位（如192.168.1.1），IPv6是128位。
- **IP数据包**：网络层的传输单元。包含源IP、目标IP、TTL、协议类型等信息。
- **路由表**：路由器维护的"导航地图"，记录目标网络→下一跳→出口接口的映射。
- **子网划分**：通过子网掩码将IP地址分为网络部分和主机部分。如192.168.1.0/24表示前24位是网络部分。
- **路由协议**：OSPF（内部网关协议）、BGP（外部网关协议）等，帮助路由器自动学习和更新路由信息。
- **TTL（Time To Live）**：每经过一个路由器减1，到0则丢弃。防止数据包在网络中无限循环。

> 网络层解决的是**跨网络端到端**的通信问题。它不关心物理介质，不关心MAC地址，只管把数据包从源IP送到目标IP。

### 第4层：传输层（Transport Layer）

**一句话：负责端到端的可靠（或不可靠）数据传输。**

关键概念：

- **TCP（传输控制协议）**：面向连接、可靠传输。提供流量控制、拥塞控制、差错重传。适用于网页、邮件、文件传输等需要数据完整性的场景。
- **UDP（用户数据报协议）**：无连接、不可靠传输。速度快但不保证送达。适用于视频直播、在线游戏、DNS查询等对实时性要求高的场景。
- **端口号**：标识主机上的具体应用进程。范围0-65535。0-1023是知名端口（HTTP=80，HTTPS=443，DNS=53）。
- **三次握手**：TCP建立连接的经典流程——SYN → SYN-ACK → ACK。
- **四次挥手**：TCP断开连接的流程——FIN → ACK → FIN → ACK。

> 传输层解决的是**进程到进程**的通信问题。有了IP能找到主机，有了端口号才能找到主机上的正确应用程序。

## 数据封装过程

数据从应用层到物理层，每经过一层就加一个头部（Header），这个过程叫**封装**：

```
应用层数据
  → +TCP头 → 段（Segment，传输层）
    → +IP头 → 包（Packet，网络层）
      → +MAC头+FCS尾 → 帧（Frame，数据链路层）
        → 转换为比特流（物理层）
```

接收方从物理层到应用层，逐层解封装，剥掉对应的头部，最终得到原始数据。

## 为什么OSI是七层而非五层？

OSI模型在设计时希望覆盖所有可能的通信场景和协议，是一种**理论模型**。而实际互联网使用的是更简洁的**TCP/IP四层模型**（应用层、传输层、网络层、网络接口层），将OSI的上三层合并为应用层，下两层合并为网络接口层。

理解OSI七层模型的目的不是记住每一层的名字，而是建立**分层思维**——当你排查网络问题时，从下往上逐层定位：物理层（网线插了吗？）→数据链路层（MAC地址对吗？）→网络层（IP通吗？路由对吗？）→传输层（端口对吗？防火墙拦了吗？）→应用层（服务在跑吗？配置对吗？）。
